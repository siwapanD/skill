# เวิร์กโฟลว์สำหรับการพัฒนา — วงจรชีวิตของฟีเจอร์ในรีโปนี้

ขั้นตอนการทำงานจริงสำหรับงาน full-stack ที่นี่ (Next.js + Oracle) ตั้งแต่ไอเดียไปจนถึงการปล่อยใช้งาน และสกิลที่ถูกเรียกใช้ในแต่ละขั้นตอน สกิลที่มีเครื่องหมาย `/name` คือคำสั่งที่ผู้ใช้เรียกเองด้วย slash command; ส่วนที่เหลือ Claude จะเลือกหยิบมาใช้เองเมื่อสถานการณ์ตรงกัน

สรุปสั้น ๆ: **`/grill-me` ก่อนเริ่มงานใหญ่ใด ๆ → ให้ Claude รันเกตต่าง ๆ → `/code-review` ก่อน merge** อย่างอื่นด้านล��างนี้จะถูกเรียกใช้ตามความเหมาะสมของสถานการณ์

## 1. ก่อนเขียนโค้ด — คิดก่อน

- ฟีเจอร์ที่ไม่ใช่งานเล็ก → `/grill-me`: ถามกลับเป็นรอบ ๆ จนกว่าพลนจะมั่นคง
  (Claude อาจเรียก `grilling` เองเมื่อเห็นว่าพลนยังไม่แน่นพอ)
- ต้องการข้อเท็จจริงจากเอกสาร/API ภายนอก → `research`: รันเป็นเอเจนต์เบื้องหลัง และผลลัพธ์จะถูกบันทึกเป็นไฟล์ Markdown แบบมีการอ้างอิง ขณะที่คุณยังทำงานต่อได้
- ไม่แน่ใจว่า state model หรือรูปแบบ UI ควรเป็นอย่างไร → `prototype`: โค้ดชั่วคราวเพื่อหาคำตอบ โดยจะไม่ถูก merge
- กำลังตัดสินใจว่า interface หรือ seam ควรวางตรงไหน → `codebase-design`

## 2. สร้างงาน — scaffold โครง แล้วทดสอบตรรกะด้วย TDD

- Scaffold ด้วย `new-page` / `new-component` / `new-server-action` / `new-api-route`
  (ตัวหลังใช้เฉพาะ webhook / external API เท่านั้น — mutation ปกติให้ใช้ Server Actions)
- ฝั่งฐานข้อมูล: ไฟล์ migration ใหม่ใน `lib/db/migrations/` (forward-only) + ฟังก์ชัน query ใน `lib/db/queries/` (bind variables, typed rows)
- ตรรกะที่มี seam ชัดเจน → `tdd` (red → green)

## 3. เมื่อเกิดบั๊ก

- บั๊กที่แก้ยาก → `diagnosing-bugs`: สร้าง repro ก่อนตั้งสมมติฐาน
- แก้แล้วและยืนยันผลแล้ว → `/post-mortem`: บันทึก root cause, mechanism, validation, และสาเหตุที่หลุดรอด ลงใน `docs/postmortems/`

## 4. ก่อนบอกว่างานเสร็จ — เกตตามลำดับ

```text
tsc --noEmit → lint → vitest → next build
```

ฟีเจอร์ที่ผู้ใช้มองเห็นได้ต้องมี Playwright happy-path test อย่างน้อยหนึ่งตัว Claude จะรันเกตเหล่านี้ก่อนรายงานว่างานเสร็จ (กฎการทำงานของรีโป ข้อ 1)

## 5. รีวิวและปล่อยใช้งาน

- `/code-review` สำหรับบั๊ก, `/simplify` สำหรับโค้ดที่เยอะเกิน, `/security-review` ก่อน merge branch ที่สำคัญ
- ใช้ conventional commits (`feat:` / `fix:` / …) การทำ migration ต้องปล่อยก่อนโค้ดที่พึ่งพามัน Claude จะไม่ push หรือ deploy ถ้าไม่ได้รับการขอ

## 6. เซสชันยาว ๆ

- หยุดงานหรือสลับเครื่อง → `/handoff`: ย่อบทสนทนาเป็นเอกสาร handoff สำหรับเซสชันถัดไป
